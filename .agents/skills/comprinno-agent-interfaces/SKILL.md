# Comprinno agent interfaces

Read `AGENTS.md` for the security and deployment invariants, and the relevant installed Next.js guide in `node_modules/next/dist/docs/` before modifying routes, rewrites or caching. These interfaces expose public website content through shared logic.

## Follow the shared implementation

| Concern | Source and adapters |
| --- | --- |
| Search and tool definitions | `src/lib/agentApi.ts` |
| MCP transport | `src/app/mcp/route.ts` |
| Browser registration | `src/components/WebMcpTools.tsx` |
| Site index and page Markdown | `src/lib/agentDocs.ts`, `src/app/llms.txt/route.ts`, `src/app/api/md/[[...path]]/route.ts` |
| Markdown negotiation | `src/proxy.ts` |
| Discovery catalogs and public skill documents | `src/lib/agentDiscovery.ts`, `src/app/api/agents/[...doc]/route.ts` |
| Authentication | `src/lib/oauth.ts`, `src/app/oauth/`, `src/app/auth.md/route.ts` |
| Public aliases and discovery headers | `next.config.ts`, `src/app/robots.ts` |

Change shared tool behavior in `agentApi.ts`, then inspect its transport and discovery consumers. Preserve public, read-only behavior and advertise only working capabilities. The repo's local development skills under `.agents/skills/` are separate from public skill documents generated by `agentDiscovery.ts`.

Browser tools are defined separately: WebMCP currently offers `search_content`, `get_page`, `open_page` and `get_contact_info`; MCP offers `get_site_index` in place of `open_page`. WebMCP search/contact delegate to MCP, page reads use Markdown negotiation and navigation uses the router. Keep those intentional differences when updating schemas or descriptions. Feature detection accepts `document.modelContext` or `navigator.modelContext`.

`pageMarkdown()` is explicit route mapping, not HTML conversion. Adding a page does not automatically add its Markdown representation. When extending coverage, compare the human page, Markdown response, index and search result for consistent URLs and facts.

`src/proxy.ts` rewrites page requests with `Accept: text/markdown`. Preserve its exclusions for API, OAuth, MCP, Next internals and files. Markdown responses carry `Vary: Accept` and a token estimate; missing content returns 404.

Public discovery aliases are individually listed in `next.config.ts`. Add aliases alongside their handler branches; retain the certificate-challenge exclusion described in `AGENTS.md`. Skill index digests are computed from generated document bodies, so update the source generator rather than hand-writing digest values.

## Check observable protocol behavior

For interface changes, build and run a local server on an available port. Check only the surfaces affected, expanding checks when shared code changes:

- Request an existing page as HTML and with `Accept: text/markdown`; verify content, headers and an unknown-path 404.
- POST JSON-RPC `initialize`, `tools/list` and a relevant `tools/call` to `/mcp`. Verify returned tool names/schemas against `agentApi.ts`. Notifications return 202 with no response body; GET is 405 and OPTIONS is 204.
- Retrieve the relevant public `/.well-known/` aliases, checking content types and advertised URLs. For public skill changes, compare each index digest to the actual served body using SHA-256.
- For browser tool changes, inspect feature detection and registration in a browser that supports `document.modelContext`; absence of that API is an expected fallback.

When OAuth is enabled, a supplied invalid MCP token must return 401 with `WWW-Authenticate`; anonymous access remains available. The current transport performs token validation only when OAuth is enabled, so distinguish enabled and disabled configurations in verification.

## OAuth and build-time configuration

Before changing authentication, read `src/lib/oauth.ts` and all affected handlers together. Retain the public-read scope, PKCE, redirect validation, explicit consent click, same-origin consent POST protection and response security headers documented in `AGENTS.md`.

Test disabled behavior with no signing key: OAuth endpoints and metadata return 404 and `auth.md` reports anonymous access. Test enabled behavior with a temporary local test key kept outside tracked source; never print production keys or token-bearing URLs. Exercise the consent flow in a real browser by clicking Continue, in addition to scripted token checks.

With Cache Components enabled, request-independent GET responses may be prerendered and environment values baked in. Set the intended origin and OAuth configuration before building, and rebuild when switching configurations. Compare enabled/disabled discovery with the actual authorization routes so cached metadata does not advertise unavailable functionality.
